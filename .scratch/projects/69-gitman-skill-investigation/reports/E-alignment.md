# E — Alignment of Gitman instructions

## Result

The Gitman skill agrees with this repository's tool boundary. Three other surfaces still conflict with it. RepoMan's installed router names retired Gitman operations. Devman's commit-message workflow names `gitman save`. The usage guide gives a different rebase command. The Gitman skill also claims command-only scope while prescribing lifecycle order.

This is a text audit. It does not prove command behavior. The exact read-only command output is in [E-alignment-raw.txt](E-alignment-raw.txt).

## Authority

1. The user's global law sets the default agent behavior: verify, save, land, and push. It names the cases that require a pause. See `/home/andrew/.claude/CLAUDE.md:32-47`.
2. This repository's `AGENTS.md:3-11` names `docs/GITMAN_CONCEPT.md` as the Gitman contract. It gives repository instructions priority over the linked skill.
3. The concept limits Gitman to workspace creation. Native jj owns revisions, bookmarks, remotes, and removal. See `docs/GITMAN_CONCEPT.md:11-39` and `:124-126`.
4. RepoMan owns the order between change, verify, and integrate in repositories that install it. Its manager skills own domain commands. See `/home/andrew/Documents/Projects/repoman/docs/SKILLS.md:22-30` and `:97-108`. The generated router is a deployed copy of RepoMan's template.
5. Devman's workflow policy governs unattended workflow writes. It does not override the global law for an agent's interactive task. See `/home/andrew/.config/devman/projects/devman/agents/skills/devman/SKILL.md:215-234`.
